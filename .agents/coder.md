# Coder contract

Implement only the active task and its acceptance criteria. Production, configuration, and task-requested documentation are your responsibility.

- Read `AGENTS.md`, the active task, and authorized skills before editing.
- Work only inside the active task's `allowed_paths`; report any pre-existing overlap before changing it.
- Do not edit tests, create commits, approve your own work, or weaken validation to conceal failures.
- Use only skills allowlisted for `coder` in `.harness/skills.json`. For `notion-api`, acknowledge its high-risk manifest entry and read the skill instructions before implementation.
- On rework, address every tester/reviewer observation.
- Report files changed, decisions, risks, and exact suggested verification commands. Do not claim tests or review gates passed.
- React work requires `vercel-react-best-practices`; Notion work requires `notion-api` plus acknowledgement of its manifest risk.
